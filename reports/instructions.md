# How to Fill Out the Weekly Status Report

## Quick Start

1. Copy [template.md](./template.md) and save it as `status-YYYY-MM-DD.md`, using the **Friday** date of the reporting week (e.g., `status-2026-10-16.md`).
2. Replace every `[bracketed placeholder]`.
3. Submit by **end of day Friday** (or the agreed deadline).

See [example.md](./example.md) for a completed report.

## General Guidelines

- Keep it to one screen or less; it should be readable in under 3 minutes.
- Be specific and factual. Prefer numbers and dates over vague wording.
- Write accomplishments in past tense and plans in future tense.
- Report outcomes (what was delivered), not activities (what you worked on).
- Remove a section only if it truly doesn't apply; otherwise write "None."
- Carry forward open risks and metrics from last week so trends are visible.

## Section by Section

### Header table
- **Week**: Monday to Friday of the reporting week.
- **Prepared By**: The person accountable for the content.
- **Date Submitted**: The day you send the report.
- **Overall Status**: Choose one.
  - 🟢 **On Track**: Scope, schedule, and budget are within plan.
  - 🟡 **At Risk**: A problem could cause a miss if not addressed soon.
  - 🔴 **Off Track**: A target is already being missed; intervention is needed.
- **Status Change vs. Last Week**: Compare with last week's report: Improved, Unchanged, or Worsened.

### 1. Summary
Two or three sentences: how the week went, the key outcome, and why the status is not green (if applicable).

### 2. Done This Week
Completed work only, 3–7 bullets. Mention resolved risks or issues here.

### 3. Planned for Next Week
Work you commit to finishing next week. Keep it realistic for five working days and tie items to milestones where possible.

### 4. Milestones
One row per key deliverable. Use **Done**, **On Track**, **At Risk**, or **Delayed**. If a date moved, write "old → new" in Notes.

### 5. Risks and Issues
- **Risk**: might happen. **Issue**: already happening.
- **Impact**: High, Medium, or Low.
- Every row needs an owner and a due date for the mitigation.
- When resolved, remove the row and note it under Done This Week.

### 6. Metrics
Track 3–5 measures that stay the same every week. Fill in the target, this week's value, last week's value, and a trend arrow (⬆ improving, ➡ flat, ⬇ worsening).

### 7. Help Needed / Decisions
State the specific ask, who must act, and by when. Write "None" if nothing is needed.

## Submission Checklist

- [ ] File named with the Friday date
- [ ] All placeholders replaced
- [ ] Overall status is consistent with the milestones and risks listed
- [ ] Every risk/issue has an owner and due date
- [ ] Metrics include last week's values
- [ ] Dates use the `YYYY-MM-DD` format
- [ ] Proofread for typos and unclear wording
